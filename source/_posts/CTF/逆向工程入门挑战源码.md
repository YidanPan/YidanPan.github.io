### 第三部分：通用寄存器大清零与条件跳转


; 每一个程序总得从某个地方开始运行，那为什么不从 `_start` 开始呢？
_start:  ; 这是一个“标签（Label）”…… 它本身并不是一条机器指令。它只是写给我们人类看的标记。我们把它放在这里是为了以后方便引用。这样一来，如果我们后面在代码里提到了 `_start`，NASM 编译器就会知道我们指的是这个标签紧跟在后面的那个元素。

  cli    ; 这条指令你平时在写普通程序时基本见不到…… 所以不用太担心。它的作用大概就是：把中断关掉，免得此时往电脑上插个 USB 闪存盘把处理器吓跑、打断我们的核心工作。

  ; 重要概念：汇编语言会给你提供一套数量固定的“变量”。这些变量被称为寄存器（Registers）。呃，严格来说它们并不是变量，但你完全可以把它们当成变量来理解。它们的速度极快。根据你调用它们的名字不同，你拿到的空间大小也不同（比如 16 位、8 位还是 64 位等等）——它们就是用来供我们存储“数据”的固定大小的格子。
  ; 接下来，我准备把我们拥有“通用”访问权限（且不会导致代码直接当场暴毙）的所有寄存器全部清零，好让你看清它们长啥样…… 实际上还有很多其他寄存器，但下面这些是我们在存储和操作数据时最常用到的“主食”。

  mov ah, 0
  mov al, 0
  mov ax, 0

  ; 好了，我得在这里先踩个刹车。让我们把上面那行代码拆开，看看它的各个组成部分：
  ;   `mov` —— 你看到的第一个单词被称为“操作码（Opcode）”，代表了你的代码让计算机处理器去执行的某个具体动作。这一个代表的是 Move（移动/赋值）。它就是用来挪动东西的。
  ;   `ah`  —— 就是我刚才提到的那些寄存器之一（也就是 'a' 寄存器…… 顺便说一下，后面还有 'b', 'c', 'd' 等等）。它的容量是 8 位（Bits）…… 这是我们能使用的最小的寄存器尺寸。
  ;   `0`   —— 它就是…… 数字零。不然你还想让我解释个啥嘛（meee）？
  ;
  ; 所以用一个你可能更习惯的语法来表达：
  ; `mov ah, 0` 实际上就等于 `ah = 0`
  ; 因为我们是在把数据从右边挪到左边…… 让 ah 这个格子装下“零”这个值。
  ; 我们对 al 和 ax 做的也是同样的事情。al 是另一个 8 位寄存器，而 ax 是 16 位的…… 不过，它们都因为字母 A 产生关联。它们其实是同一个寄存器的不同组成部分：
  ;
  ; 16 位（为了视觉效果，我把它拆成了两个 8 位的块）：
  ;
  ; -------- --------
  ;
  ; 这些是用来存放 0 和 1 的插槽…… 看起来可能像这样：
  ;
  ; 00000000 00000000
  ;
  ; 或者是我们设置的任何其他二进制值。
  ;
  ; 数字中最高位的数字在左边，这跟我们日常的数学习惯一样。因此，正如我所做的那样，我们可以把这 16 位拆成两个独立的半部分，并把它们标记为 high（高位，简称 h）和 low（低位，简称 l）…… 较高的 8 位是更重要的有效数字（高位数字）。
  ; 为了方便，我们可以完全独立地去操作这其中的每一个半部分。我们只需要知道怎么引用它们就行了：
  ;
  ; -------- --------
  ;    AH       AL
  ;
  ; 而这整个整体，就被称为 AX。
  ;
  ; 这一点非常重要，所以，我再重申一遍…… 如果你想改变 A 寄存器的任何一部分，你需要指明你想改变它的哪一部分。是整个 16 位，还是低 8 位，亦或是高 8 位。必须要“精确到比特”（Specif-bits，作者在开谐音梗）。我知道，我可真幽默。
  ;
  ; 我们手里拥有的 A、B、C、D 寄存器全都是这种结构。稍后我们还会接触到 8 到 15 号寄存器，它们也类似，但等碰到了再聊。

  ; 让我们继续清空我们的寄存器…… 只是为了确保我们刚开始的时候它们全都是 0，顺便让你看看它们都长啥样：

  mov bh, 0
  mov bl, 0
  mov bx, 0 ; 请意识到，最后这一行其实是多余且毫无意义的（因为前面两行已经把高低部分都清零了）。

  mov ch, 1
  mov cl, 1
  mov cx, 0 ; 无论前面设置了啥，之前的两个值都会被这一行无情覆盖。在这条指令执行完后，组成 cx 的两个部分（ch 和 cl）的值都会变成 0，而不是 1。

  ; 为了证明我刚才说的话，让我们引入一个快捷的比较指令…… `cmp`（Compare）
  **条件判断：**
  cmp ch, 1  ; 许多指令在执行时，**影响的局限于显式写出来的操作数**。在这个例子中，它会悄悄设置一个名为 `flags`（标志寄存器）里的某些特定位。标志寄存器的每一个二进制位都被用作一个布尔值（True/False）。不过你不需要去死记硬背每一个位代表什么布尔值，因为我们有其他的操作码会去自动读取并解析这个标志寄存器。
  ; 这条指令会盯着寄存器 ch 和绝对值 1，并根据它发现的属性（小于、大于、等于等）来设置 flags 里的各个字段。

寄存器:cpu中可以寄存数据的器件（用来快速存储数据，速度快但是存储容量小。）
有四大通用寄存器，abcd，用来存具体数据。`flags` 寄存器非常特殊，它是 CPU 内部的**一个“状态仪表盘”**。这个寄存器的每一位都是布尔变量，true或者false，分为零标志位，符号标志位，进位标志位。
先通过cmp比较如果是1则零标志位标志成true，如果是0则零标志位标志成false，符号标志位标志成true

  je .death  ; 读作“Jump if Equal”（等于则跳转）。如果之前比较的两个值在比较时是**相等**的，那么程序就会跳转到作为唯一操作数指定的“标签”（还记得之前的 `_start` 吗？）处去执行。这条指令同样作用于一个没有明确写出来的寄存器…… 那就是“指令指针寄存器（IP）”，它实际上保存着我们下一步要执行的指令在内存中的计数。
  
  jmp .next_test ; 既然刚才那两个值不相等（因为 cx=0 导致 ch=0，0 不等于 1），没有满足跳转条件，程序就会直接“顺着滑落”到下一条指令，也就是这一条。这一条是一个“**无条件跳转**”，直接帮我们绕过下面的死亡代码块。
  
  .death:
    hlt  ; “Halt and catch fire”（挂起并自焚指令）—— **立即停止执行任何代码**。当场去世。永远别想回来。一切都结束了。天上的死亡激光射中你了。诸如此类。
  
  .next_test:  ; 顺便提一句，我这里使用的是 NASM 汇编器，它提供了很多好用的预处理器功能，非常像 C++ 里的 #include 之类的玩意。
                ; NASM 提供的功能之一就是“**局部标签**（Local Labels）”。任何前面带有一个点号（“.”）的标签，都被视为属于**上级函数（即前面那个不带点号的普通标签）的局部标签**。这样为了方便，你就可以在不同的老大哥标签内部重复使用相同的局部标签名。
    cmp cl, 0
    je .success  ; 如果 cl 确实是 0，那就跳过死亡块！

    hlt  ; 别啊（pls no）

    .success:  ; 顺便说一下，代码里的空格和缩进都会被忽略…… 就像被无视的我一样。

  ; 其实，让一个寄存器归零还有很多其他的方法…… 我希望你还记得你的二进制位运算符（与 AND、或 OR、非 NOT、异或 XOR）
  xor dh, dh  ; <- 思考题 1 （提示：自己异或自己会发生什么？）
  and dl, 0
  mov dx, 0xffff  ; 十六进制数
  not dx      ; <- 思考题 2 （提示：全满的 1 经过 NOT 取反会变成什么？）

  cmp dx, 0
  jne .death  ; 这一次如果不相等，就往回跳转到我们之前路过的死亡标签…… 这样能避免写重复的代码。

> 关于**局部标签举个例子**：
> _start:              ; 👑 这是全局大路标（老大）
>   cli
>   ...
>   je .death          ; 👈 这里其实完整的意思是：跳到 "_start 内部的 death"
>   jmp .next_test     ; 👈 这里完整的意思是：跳到 "_start 内部的 next_test"
>   
>   .death:            ; 📌 局部路标（附属在 _start 门下）
>     hlt  
>   
>   .next_test:        ; 📌 局部路标（附属在 _start 门下）
>     cmp cl, 0
>     je .success
> 
> new_function:        ; 👑 新的全局大路标（新老大诞生！）
>   ...
>   jmp .end
>   
>   .end:              ; 📌 又是局部路标 .end，但它现在自动绑定了 new_function！

### 第五部分：利用 BIOS 中断一个字一个字打印字符串

; 定义一个新函数
new_function:
  ; 如你所见，它并不是什么真正的新函数…… 既然空格和标签都会被编译器忽略，我只是在源码文件里标记了一个新位置而已。

  ; 【终极目标】：**让我们在屏幕上打印一些文字**！

  ; 第一步：我们需要设置一下屏幕，好让它允许我们显示文本。
  mov ax, 0x0003     ; **设置文本显示模式**；相当于ah是0x00，al是0x03
  int 0x10          ; 啊哈！新玩意儿登场了！**触发 BIOS 中断**。
  
ah=0x00时是在说要现在要设置显示器的画面模式，al=0x03是在说把屏幕切成80$*$ 25字符的纯文本黑底模式（首先是设置好ax，所以在后面中断bios的时候才可以达到这个效果）

  ; 第二步，遇到了一个问题：**我们一次只能打印一个字母**，像这样：
  mov al, 't'        ; 把字符 't' 装入 al（把字符t的ascall码值装进al）
  mov ah, 0x0e      ; 告诉 BIOS：我要使用“电传打字机模式”打印单个字符！<- 思考题 4（提示：看下面关于 0x0e 功能的解释）
  int 0x10          ; 又是这个新东西。好吓人！

  ; `int` 代表中断（Interrupt）。退一步站在程序员的角度来看，我们写的代码除了**操纵数据**和**做决定（分支跳转）** 之外，其实什么都干不了。
  ; 如果我们想让我们写的东西产生真正的实际影响，我们就必须**和外部环境交互**——把代码里倒腾的数据显现出来，让最终用户能看到。
  ; 这意味着我们必须调用系统留给我们的 API。在这个操作系统的世界里，我们需要和**主板的系统——BIOS** 打交道，并拜托它替我们去和**屏幕交互**（以后可能还要和 USB 驱动器之类的交互）。
  ; 我们在这里调用的中断号是 0x10。你可以去维基百科查阅 INT 10H 的所有功能。**简而言之，根据 AH 寄存器里的值的不同，这个中断能干完全不同的活。** 当 AH = 0x0e 时，它允许我们把存储在 AL 寄存器里的 8 位 ASCII 码字母直接打印到屏幕上。

  ; 但这感觉有点鸡肋。一次只能打印一个字母。我们可以写得更高级一点。

  ; 首先，让我们定义一串用来打印的字符串。但请记住：现在我们是在代码堆里硬生生定义了一块“垃圾数据”，所以我们必须在程序运行到它之前“飞跃”过去，免得 CPU 误把我们的文本字符串当成机器指令去解码执行。
  mov ax, .string_to_print  ; 把字符串的内存首地址交给 ax
  jmp print_string          ; 飞跃到打印函数去
  .string_to_print: db "acOS", 0x0a, 0x0d, "  by Elyk", 0x00  ; 格式：标签: <元素大小> <元素数组>
  ; **`db` 代表 Define Bytes（定义字节）** 意思就是把后面的字符在后面的内存中一个一个存入。类似的还有 db, dw, dd, dq, dt, do, dy, 和 dz。我刚才甚至惊奇地发现最后那三个竟然真的存在。这不算什么汇编特有知识，不记得也没关系。
  ; 数据的定义可以是“字符串”的形式，也可以是用逗号隔开的值。
  
db后面引号内的是需要打印的字符串，在后面的字符是计算机底层用来控制文本排版和标记结束的符号
- 0x0a：控制屏幕的光标**垂直向下移动一行**，但光标的横坐标不变。如果只执行这一步，光标会悬在下一行的正中间。,
- 0x0d：把光标**狠狠地甩回到当前行的最左边（起始位置）**，
- "  by Elyk"：这就没什么意思了，纯粹是作者的硬编码署名、
- 0x00：汇编语言中的NULL，代表字符串到这里就结束了。一般所有字符串的终止应该都是0x00

; 现在我们来写一个能**打印一整串字符串**的“函数”
print_string:
  .init:
    mov si, ax  ; 因为我们从语法上没办法像高级语言那样传参，所以我直接用 ax 来充当第一个参数——把要打印的字符串指针传给 si。（ax什么都是通用寄存器，能够比较好的存储各种数据）

  .print_char_loop:
    cmp byte [si], 0  ; **表达式加上方括号 `[...]` 代表“取……地址里的内容**”，这跟 C 语言里的指针解引用操作（*ptr）完全一模一样！
                        ; 所以在这里，si 是一个指针（它是从 ax 复制过来的字符串首地址）
                        ; 如果我们当前指到的地方是一个零（Null-byte），说明我们撞上了字符串的末尾——这就是所谓的“以 0 结尾的字符串”（参考上面 178 行末尾定义的 0x00）
    je .end            ; 如果撞到 0，说明打完了，跳出循环。如果相等就跳转到end
   
    mov al, [si]  ; 既然方括号是解引用，这就是把 si 指向的那个“单字节字符”抓出来丢进 al 里：`al = *si`这一步真正实现了内存数据到寄存器的转移，把数据真正存在了寄存器中

    mov ah, 0x0e  ; <- 思考题 5！（提示：循环到第三次时，ah 的值被改成了什么？）
    int 0x10      ; 这个指令可以让cpu呼叫 烧录好的BIOS，真正把字符打印在屏幕上。bios看到ah中装的是0x0e就知道是要打印单个字符，然后打印al中的字符
 
    inc si        ; 指针自增 1，走到下一个字符的地址 （inc是increment自增的意思）
    jmp .print_char_loop 无条件跳转到循环开始
    .end:

### 第七部分：极其复杂的“打印数字”函数

代码段

```
; 这个函数负责把存储在 AX 里的十六进制或二进制数字转换成人类看得懂的十进制字符并打印出来……这在汇编里可不是个简单的活。
newline: 
  db 0x0d, 0x0a（回车换行）
print_buf:
  resb 5          ; 预留 5 个字节的缓冲区
  db ' ', 0
print_rax:
  lea si, [print_buf + 4]       ; 我们的策略是通过“除以 10 取余数”的数学方法，从右往左逆向构建数字字符串，所以指针先指向缓冲区的末尾。
  ; 顺便解释一下这个神奇的 `lea`（Load Effective Address）操作码…… 它简直就像黑魔法。
  ; 在方括号 `[...]` 里面，最复杂的表达式可以写成 `[寄存器1 + 寄存器2 * 常数1 + 常数2]`
    ; 寄存器1 叫 基址（Base）
    ; 寄存器2 叫 变址（Index）
  ; 绝大多数时候方括号代表去内存里取值，但 `lea` 极其叛逆，它偏不取值，它只负责把括号里算出来的“纯地址结果”直接抢过来。这样能当成高级数学计算的快捷方式，省得去反复调用 `add` 指令。

  mov di, si                    ; 备份最后一位字符的地址
  mov bx, 10                    ; 把除数 10 存进 B 寄存器

  .div_loop:
    ; 汇编里的除法有点怪，但用起来很爽。
    ; 除法指令非常简单，就写 `div 操作数`，它会自动把 A 寄存器里的值拿去当被除数。
    ; 除法的结果（商）会被存进 rax，而余数则被丢进 rdx。但在做除法之前，必须手动把 rdx 清空，否则数据会乱套。
    xor dx, dx                    ; 异或清空 dx，为除法做准备
    div bx                        ; 执行除法！(商:余数) = ax / bx
    add dx, 0x30                  ; 把得到的数字加上 0x30，转换成 ASCII 码格式（比如数字 0 变成字符 '0'）
    mov byte [si], dl             ; 把余数（字符）存入缓冲区
    dec si                        ; 指针向前挪一位，准备存“十位数”
    cmp ax, 0                     ; 检查商是不是已经变成 0 了（数字是不是除光了）
    jz .check_buf                 ; 如果除光了，跳出循环
    jmp .div_loop

  .check_buf:
    cmp si, di                    ; 检查我们有没有真的往里写过数字
    jne .print_buf
    mov byte [si], '0'            ; 如果啥都没干，那这个数就是 0，往里写个 '0'
    dec si

  .print_buf:
    inc si                        ; 指针校准，指向数字字符串的开头

    .print_char_loop:
      cmp byte [si], 0           ; 检查是否撞上了缓冲区末尾
      je .end

      ; 在输出字符之间故意“睡”一小会儿，因为我是一个冷酷又非主流（3dGY and C00l）的黑客
      push cx
        push dx
          push ax
            xor cx, cx
            mov dx, 0xffff
            mov ah, 0x86
            int 0x15              ; 呼叫延迟中断，让屏幕卡顿一下营造极客范
          pop ax
        pop dx
      pop cx

      mov al, [si]               ; 取出字符
      mov ah, 0x0e                ; 打印它
      int 0x10
  
      inc si
      jmp .print_char_loop
.end:
ret                               ; 函数返回
```

### 第八部分：内存栈（Stack）的“大变魔术”演示

代码段

```
print_info:
  mov ax, bp  ; 打印基址指针寄存器 BP 的当前值
  call print_rax
  mov ax, sp  ; 打印栈指针寄存器 SP 的当前值
  call print_rax
ret

stack_example:
  mov ax, 1
  push ax  ; 【压栈】：把 ax 的值（1）强行塞进内存栈里保存起来。
    call print_rax  ; 哦顺便说一句，汇编里确实是有“函数调用”的！就是用 `call`。它会悄悄把当前执行到的指令位置（ip）存下来，等函数里面执行到 `ret` 时，又能原路返回到这里接着往下跑。
    call print_info  ; 观察这次打印出来的两个值…… 你会发现一个纹丝不动，另一个上蹿下跳。

      mov ax, 2
      push ax      ; 继续压入 2
        call print_rax
        call print_info  ; 【核心观察点】：BP（栈底）的值一直没有变

        mov ax, 3
        push ax    ; 继续压入 3
          call print_rax 
          call print_info  ; 【核心观察点】：随着数据越塞越多，SP（栈顶）的值一直在疯狂改变！

          mov ax, 4
          push ax  ; 继续压入 4
            call print_rax
            call print_info

            mov ax, 5
            push ax ; 继续压入 5
              call print_rax
              call print_info

          pop ax  ; 【出栈】：把栈顶最后塞进去的东西弹出来复原（先进后出原则 FILO）
          call print_rax
          call print_info  ; 当我们把东西一个个拿出来时，SP 奇迹般地往回退，恢复到了原本的数值！

        pop ax
        call print_rax
        call print_info

      pop ax
      call print_rax
      call print_info  ; 程序员通常利用 BP 和 SP 之间的这一段距离，在内存里圈出一块专属于某个函数的私密领地，用来存放局部变量。这东西就叫做【栈帧（Stack Frame）】。这是一个存储临时变量的绝佳手段。

    pop ax
    call print_rax
    call print_info  ; 事实上，所有的高级语言编译器（如 C++、Java），底层都是把函数的局部变量这么死死捏在栈里面的。

  pop ax
  call print_rax
  call print_info
```

# 编译 vs 汇编

- 编译：高级语言->汇编语言（源代码->目标文件->可执行文件）从目标文件到可执行文件是链接
- 汇编：汇编语言->机器语言
- 反编译 可以查表获得 比较准确
- 反汇编：从机器语言到汇编语言

- **Clang：** 负责看懂 C/C++ 代码并做语法检查。把高级语言翻译成llvm ir语言 
    
- **LLVM：** 负责后续的优化和生成二进制 ELF 文件。把llvmIR语言翻译成汇编语言

# GDB

- 定义：GNU Debugger
- 三大能力：
	- - **断点拦截（Breakpoint）：** 你可以在程序的任何地方（某个函数、某行汇编、甚至某个特定的内存地址）设立一个“红绿灯”。程序运行到这里时会**立刻静止**。
	- **内存与寄存器透视（Examine / Inspect）：** 程序静止后，你可以像医生拍 X 光片一样，去查看当前 CPU 每一个寄存器（如 `rax`, `rsp`, `rip`）里面存了什么数值，栈空间（Stack）里排布了什么数据，堆内存（Heap）长什么样。
	- **单步微操（Step / Next）：** 你可以让程序像播放幻灯片一样，**走一步、停一下**。你可以按汇编指令一行一行地执行（`si` / `ni`），亲眼看着数据是如何在寄存器和内存之间搬运的，从而精准捕捉到漏洞触发的那一瞬间。
- 相当于就是一个动态编译器 可以随时断点单步执行

# 算法

- tea：微型加密算法  在 Tea 算法中其最主要的识别特征就是 拥有一个 magic number ：0x9e3779b9 。
- RC4：对称加密(普通加密都是块加密，这里使用的是流加密，就是来一个字节就加密一个字节)
	- 判别的三大特征：
		- **数字 `256`（或十六进制 `0x100`）：** 代码里一定会出现循环 256 次的 `for` 循环（因为要初始化 256 字节的 S 盒）。
		- **递增赋值：** 看到类似 `S[i] = i` 这样的初始化代码。
		- **频繁的两数交换（Swap）**
- 代码混淆：
	- 花指令：如利用 jmp 、call、ret 指令改变执行流
	- 自修改代码：在运行时修改自身代码，从而使得程序实际行为与反汇编结果不符。
	- 控制流平坦化：ollvm  增加一些指令和一些case条件，使得程序的分支变多变复杂（它可以把原有程序分支全部都转换成同一层级的代码）

# 程序

- 预处理：此阶段处理所有以 '#' 开头的预处理指令。例如，展开头文件、进行宏替换、处理条件编译指令(`#ifdef`)，并清除注释。输出文件依然是可读的 C++ 代码，但体积显著增大。
- 编译：编译器对预处理后的 `.i` 文件进行语法分析、词法分析、语义分析及优化，并将其翻译成特定硬件架构（如 x86-64）的汇编指令（`.s` 文件）。在此可以观察到常量折叠优化（5*5 变为 25）。 编译是翻译成汇编语言
- 汇编：汇编是翻译成机器码。汇编器将 `.s` 中的汇编指令一对一翻译成机器指令（二进制码），并生成可重定位目标文件（`.o`），通常符合 ELF 格式。此文件已是不可直接阅读的乱码（右侧以十六进制展示指令编码）。
- 链接：链接器将多个目标文件（`.o`）以及系统静态/动态链接库合并，解析相互引用的符号，修正外部函数及全局变量的地址（重定位），最终产生可在操作系统下直接运行的二进制文件。

**为什么要加 `./`？** 这是 Linux 的一个安全机制。当你在终端输入一个命令（比如 `cd` 或 `g++`）时，系统会去系统环境变量（`PATH`）指定的目录里找这些程序。为了防止你意外运行或者被恶意替换当前目录下的同名文件，Linux 不会默认在“当前目录”下找程序。`./` 的意思就是明确告诉系统：“**请执行当前（`.`）目录下的（`/`） `rev_begin` 文件**”。

### clang
是另一个与gcc齐名的c/c++编译器。早期苹果公司在使用 GCC 时，觉得 GCC 的代码架构太老旧、太臃肿，而且有诸多限制，于是决定从头写一个全新的编译器，这就是 Clang
- **🏆 极其友好的人类级报错信息（最直观的体验）：** 你刚才用 `g++` 遇到报错时，可能感觉有些干瘪。而 Clang 最大的卖点就是它的报错信息非常精准！它不仅会告诉你哪一行报错，还会用小箭头 `^` 精准指到是**哪一个字母**出了问题，甚至会极其智能地提示你：“_你是不是拼错变量名了？你是不是少了一个分号？_”。
- **⚡️ 编译速度更快，内存占用更小：** 在大型项目中，Clang 的编译速度通常比 GCC 更快，能替程序员省下大量喝茶等待的时间。
- **🛠️ 强大的周边工具链：** 因为 Clang 的底层架构（LLVM）设计得非常模块化，现在市面上几乎所有好用的 C/C++ 开发工具都在用它。比如你用的代码高亮补全插件（`clangd`）、代码自动格式化工具（`clang-format`）、代码静态检查工具（`clang-tidy`），底层全都是基于 Clang 的。

- **Clang 是“前端”：** 它负责读懂你写的 C/C++ 源代码，检查你的语法对不对，然后把它翻译成一种“中间语言”。
- **LLVM 是“后端”：** 它接手这个“中间语言”，负责疯狂优化它，最后把它翻译成不同 CPU（如 x86, ARM, 苹果 M 系列芯片）能听懂的底层汇编/机器码。是底层架构。

	**LLVM IR** 是一种**介于高级语言（C++）和底层机器码（汇编）之间的一种强类型、虚拟指令集代码**。它比 C++ 纯粹，又比底层 x86 汇编更具有可读性。

- 同一个文件在不同架构下生成的机器码是不同的


# 大端序vs小端序
**大端序（Big-Endian）** 大端序的存储逻辑非常符合人类从左到右的阅读习惯。它会将数据的最高有效字节存放在最低的内存地址上。
**小端序**的存储逻辑刚好相反，会把最高有效字节放在最高的内存地址上。

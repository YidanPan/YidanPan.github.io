# Heap sort

- 最先关注的就是这个是大根堆还是小根堆
## 一、核心基础：什么是“堆”？

在学习堆排序之前，必须先明确“堆”这一特殊数据结构的物理存储与逻辑结构。
### 1. 堆的两个核心特征

- **结构性（完全二叉树）**：堆在逻辑上必须是一棵**完全二叉树**。这意味着除了最后一层外，其余层的节点都是满的，且最后一层的节点都连续集中在左边。
    
- **有序性（堆序性）**：
    
    - **大顶堆（Max Heap）**：任何一个父节点的值都**大于或等于**它的左右孩子节点的值（`A[i] >= A[2i]`）。常用于**升序排序**。
        
    - **小顶堆 Min Heap）**：任何一个父节点的值都**小于或等于**它的左右孩子节点的值（`A[i] <= A[2i]`）。常用于**降序排序**或优先队列。
### 2. 堆的底层存储（数组映射）

虽然堆在逻辑上是一棵树，但在实际物理存储中，我们通常直接使用**一维数组**。通过下标的数学关系，可以完美复现树的父子关系：

> **以 1-indexed 数组为例（下标从 1 开始）：**
> 
> 如果一个节点的下标为 $i$：
> 
> - 它的左孩子下标为：$2i$
>     
> - 它的右孩子下标为：$2i + 1$
>     
> - 它的父节点下标为：$\lfloor i/2 \rfloor$
>     
> 
> _(注：如果数组从 0 开始计数，则左孩子为 $2i+1$，右孩子为 $2i+2$，父节点为 $\lfloor (i-1)/2 \rfloor$)_

## 二、 核心操作：如何维持一个堆？

堆排序之所以高效，全靠一个核心算子：**下滤（Sift Down / Down Adjust）**。

### 下滤（Sfit Down / Heapify）的原理

当某个节点的值被破坏（比如堆顶元素变小了），它就需要与它的左右孩子中**较大的那一个**进行比较：

1. 如果它比最大的孩子还要小，就和这个大孩子**交换位置**。
    
2. 交换后，该元素下降到新的位置，可能会继续破坏子树的堆序性，因此需要**递归或循环向下**继续这个过程。
    
3. 直到它比所有孩子都大，或者已经降到了叶子节点，调整结束。
    

## 三、 堆排序的完整步骤

堆排序的整体流程可以概括为两大家族任务：**“建堆”** 与 **“排序/出堆”**。

### 阶段一：建堆（Build Heap）

给你一个无序的初始数组，如何把它变成大顶堆？

- **做法**：我们从**最后一个非叶子节点**开始（下标为 $\lfloor N/2 \rfloor$），从右往左、从下往上，对每一个节点调用一次**下滤（Sift Down）**。
    
- **为什么从 $\lfloor N/2 \rfloor$ 开始？** 因为大于 $\lfloor N/2 \rfloor$ 的节点都是叶子节点，叶子节点本身已经可以看作是一个合法的堆，无需下滤。
    

### 阶段二：排序迭代（Sort Loop）

当大顶堆建好后，数组的第一个元素 `A[1]` 必然是整个数组的最大值。

1. **交换**：将堆顶元素 `A[1]` 与当前未排序区域的**最后一个元素**交换。此时，最大值成功“沉底”到了正确的位置。
    
2. **缩小边界**：有效堆的大小减 1（把刚刚沉底的最大值排除在堆之外）。
    
3. **恢复堆**：由于刚才换上去的堆顶元素是个“小兵”，破坏了大顶堆的性质，因此对新的堆顶 `A[1]` 进行一次**下滤**调整。
    
4. **重复**：重复上述 1~3 步，直到堆的大小缩减为 1，整个数组就变成了升序排列。
    

## 四、 性能与复杂度分析

堆排序在工程中非常受欢迎，主要得益于它极其稳定的高性能。

|**指标**|**复杂度 / 状态**|**原因及细节**|
|---|---|---|
|**时间复杂度（最好）**|$O(N \log N)$|即使原数组已经有序，每一轮出堆后的下滤依然要走完树的高度。|
|**时间复杂度（最坏）**|$O(N \log N)$|树的高度严格控制在 $\log N$， $N$ 次出堆调整的时间非常均匀。|
|**时间复杂度（平均）**|$O(N \log N)$|综合表现极其稳定，不像快速排序在最坏情况下会退化为 $O(N^2)$。|
|**空间复杂度**|$O(1)$|属于**原地排序（In-place）**，只需要常数级别的辅助变量用于交换。|
|**稳定性**|**不稳定（Unstable）**|在堆顶与堆底元素进行长距离交换时，会破坏相同元素的相对顺序。|

> 📊 **关于建堆的时间复杂度特殊说明：**
> 
> 很多人直觉认为建堆是 $O(N \log N)$，但通过数学错位相减法求和可以证明，**建堆的实际时间复杂度为 $O(N)$**。因为越靠近底层的节点越多，但它们下滤的高度越矮；越靠近顶层的节点越少，下滤高度才越深。

## 五、 经典标准 C 语言实现 (1-indexed)

这是一个直观、规范的 C 语言堆排序实现，方便与你之前PAT考试或课后习题的代码逻辑做对照：

C

```
#include <stdio.h>

// 交换函数
void swap(int* a, int* b) {
    int temp = *a;
    *a = *b;
    *b = temp;
}

// 大顶堆下滤核心算子：调整范围是 [root, total]
void siftDown(int A[], int total, int root) {
    int parent = root;
    int child = parent * 2; // 左孩子
    
    while (child <= total) {
        // 1. 如果有右孩子，且右孩子比左孩子大，则将目标转向右孩子
        if (child + 1 <= total && A[child + 1] > A[child]) {
            child = child + 1;
        }
        // 2. 如果最大的孩子比父亲大，则交换，并继续向下追踪
        if (A[child] > A[parent]) {
            swap(&A[parent], &A[child]);
            parent = child;     // 父亲来到孩子的位置
            child = parent * 2; // 计算新的左孩子
        } else {
            break; // 父节点已经大于等于左右孩子，调整完毕，退出
        }
    }
}

// 堆排序主函数
void heapSort(int A[], int n) {
    // 步骤 1：自底向上建大顶堆
    // 从最后一个非叶子节点 n/2 开始往前调整
    for (int i = n / 2; i >= 1; i--) {
        siftDown(A, n, i);
    }
    
    // 步骤 2：迭代排序
    for (int i = n; i > 1; i--) {
        swap(&A[1], &A[i]);  // 将当前的堆顶最大值交换到未排序区域的尾部 A[i]
        siftDown(A, i - 1, 1); // 缩减堆的边界为 i-1，并对新的堆顶进行下滤
    }
}

int main() {
    // 1-indexed 数组，A[0] 闲置，实际元素 5 个
    int A[] = {0, 50, 10, 30, 20, 40}; 
    int n = 5;
    
    heapSort(A, n);
    
    // 输出结果
    for (int i = 1; i <= n; i++) {
        printf("%d ", A[i]);
    }
    return 0;
}
```

## 💡 总结与高频考点

1. **Top-K 问题（海量数据找前 K 大）**：如果要在 1 亿个数据里找前 100 大的数，不需要全排序。只需要维护一个大小为 100 的**小顶堆**，遍历后续数据，比堆顶大的就替换堆顶并下滤。时间复杂度仅为 $O(N \log K)$。
    
2. **与快排、归并的对比**：
    
    - **快排**：平均速度最快，但最坏情况下性能不稳定，且需要栈空间。
        
    - **归并**：速度极快且稳定，但需要 $O(N)$ 的额外内存空间。
        
    - **堆排**：无论什么极端数据，时间雷打不动是 $O(N \log N)$，空间雷打不动是 $O(1)$。硬件级内存受限、要求严苛最坏打算的系统里（如嵌入式、Linux内核），堆排序常作为后备王牌。

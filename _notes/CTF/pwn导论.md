## Ret2Libc 逻辑
【第一阶段：抓取锚点】
溢出栈空间 ──> 强行调用 puts(puts@got) ──> 程序在屏幕上打印出 puts 的实时内存地址（捕获当前坐标）

【第二阶段：按图索骥】
实时 puts 地址 — 库文件中的固定偏移 = 这一刻的 Libc 内存基地址（推算出整栋建筑的地基坐标）
Libc 内存基地址 + 库文件中 system 的固定偏移 = 这一刻 system 的精准绝对地址（算出风景区的实时坐标！）

【第三阶段：垂直打击】
程序重回开头 ──> 第二次溢出栈空间 ──> 把刚刚算出来的 system 真实地址拍在 Saved RIP 上 ──> Get Shell！

执行 `system("/bin/sh")` 这行代码，在汇编层面其实是两步动作：

1. CPU 把 `"/bin/sh"` 这串字符在内存里的**绝对地址**塞进 `RDI` 寄存器。
    
2. CPU 跳转到 `system` 函数的**绝对地址**开始执行。

变量的内存布局都是从低地址向高地址分布，低地址在上，高地址在下层
c语言中读%s的时候都是读到字符串中有/x00才会停止，所以输入如果一直没有结束程序就会一直读入

### shellcode是什么
**Shellcode** 是一段**可以直接被 CPU 执行的机器码（Machine Code）**，最初用于让程序启动一个 Shell（如 `/bin/sh` 或 `cmd.exe`），因此得名 **Shell + Code** shellcode是一串可以直接放进内存里运行的字节。是汇编语言经过编译之后的机器码。汇编是一种文本语言，shellcode是一种机器语言。所以shellcode就是01串

可以做什么：
- 启动 `/bin/sh` shell控制权
- 读取 flag 文件
- 建立反向连接（Reverse Shell）
- 下载并执行其他程序
- 修改内存
- 绕过权限检查
- 调用任意系统调用（syscall）

两者最终都是机器码，只是用途不同：
- **ELF 程序**：有文件头、链接信息，由操作系统加载运行。elf只是一种文件格式，但elf程序不仅有机器码还有其他链接信息等内容，但只有机器码是给cpu执行的，其余是给寄存器调试器等内容看的。
- **Shellcode**：只有纯机器码，没有 ELF 头，可以直接复制到内存并跳转执行。shellcode只有机器码

### 系统调用

CPU 在执行你的代码时，有些事自己做不了——比如读文件、写屏幕、启动新程序。这些事必须请求操作系统帮忙。
**系统调用（System Call）理解为 Linux 内核提供给程序的一组"服务"**。
- 请求操作系统帮忙的机制就叫**系统调用**，简称 syscall。
- 系统调用不是一种语言，是一种服务。但是汇编语言就是一种编程语言（低级语言）
所以系统调用就是cpu让操作系统来帮忙干事情

Linux 给每个服务编了号：

  ┌──────┬─────────────────────────────────────┐
  │ 编号 │                服务                 │
  ├──────┼─────────────────────────────────────┤
  │ 0    │ read — 读数据                       │
  ├──────┼─────────────────────────────────────┤
  │ 1    │ write — 写数据                      │
  ├──────┼─────────────────────────────────────┤
  │ 2    │ open — 打开文件                     │
  ├──────┼─────────────────────────────────────┤
  │ 59   │ execve — 启动新程序（比如 /bin/sh） │
  ├──────┼─────────────────────────────────────┤
  │ 60   │ exit — 退出程序                     │
  └──────┴─────────────────────────────────────┘

  调用的方式：
  asm
  mov  eax, 2       ; 告诉操作系统：我要服务编号2（open）
  ; 参数放在 rdi, rsi, rdx 里
  syscall           ; 提交申请！
  ; 返回值在 rax 里

Linux常用系统调用

| 系统调用       | x86-64 编号 | 功能                     |
| ---------- | --------: | ---------------------- |
| `read`     |         0 | 从文件、终端或网络读取数据          |
| `write`    |         1 | 向文件、终端或网络写数据           |
| `open`     |         2 | 打开文件（现代程序更常用 `openat`） |
| `close`    |         3 | 关闭文件                   |
| `mmap`     |         9 | 申请一块新的内存（可读可写可执行）      |
| `mprotect` |        10 | 修改内存权限（如改成可执行）         |
| `munmap`   |        11 | 释放内存                   |
| `brk`      |        12 | 调整程序堆空间                |
| `fork`     |        57 | 复制当前进程，创建一个几乎一模一样的子进程  |
| `execve`   |        59 | 用另一个程序替换当前进程           |
| `exit`     |        60 | 结束当前进程                 |
| `kill`     |        62 | 向进程发送信号                |
| `uname`    |        63 | 获取系统信息                 |
- **PID**（Process ID）就是进程的身份证号。fork（）会返回PID值。所以不同进程就可以通过返回值来确定。

### Seccomp沙箱

- 是什么：Secure Computing Mode 在执行你的代码之前，先设了一道安检门。

 ; 先在栈上构造字符串 "flag\0"
  xor  edx, edx               ; edx = 0
  push rdx                    ; 压 8 字节的 0 到栈上（字符串结尾的 \0）
  mov  rax, 0x67616c66        ; 这串数字就是 "flag" 四个字符的编码
  push rax                    ; 压入栈，rsp 现在指向 "flag\0"
  mov  rdi, rsp               ; rdi = 字符串地址
  xor  esi, esi               ; rsi = 0（O_RDONLY = 只读）
  mov  eax, 2                 ; syscall 编号 2 = open
  syscall                     ; 执行！rax = 文件描述符 fd

  0x67616c66 怎么来的？

  每个字符对应一个 ASCII 码：

  ┌──────┬───────┬──────────┐
  │ 字符 │ ASCII │ 十六进制 │
  ├──────┼───────┼──────────┤
  │ f    │ 102   │ 0x66     │
  ├──────┼───────┼──────────┤
  │ l    │ 108   │ 0x6c     │
  ├──────┼───────┼──────────┤
  │ a    │ 97    │ 0x61     │
  ├──────┼───────┼──────────┤
  │ g    │ 103   │ 0x67     │
  └──────┴───────┴──────────┘

  x86-64 是小端序（低位字节在低地址），内存中顺序是 66 6c 61 67，拼成数字是 0x67616c66。

### AE64
AE64 是一个把普通 x86-64 Shellcode 自动转换成"只包含可打印 ASCII 字节"的编码器（Encoder）。
它的名字可以理解为：
- **A** = ASCII
- **E** = Encoder（编码器）
- **64** = x86-64 架构
AE64 就是一个编码器（Encoder），把原始 Shellcode 编码成只包含可打印 ASCII 字符的 Shellcode；等程序开始执行后，再由解码器（Decoder）恢复成原来的机器码继续执行。

### Canary（栈保护）

**栈保护**就是在缓冲区和返回地址之间放一个"哨兵"，防止缓冲区溢出覆盖返回地址。

- 栈长什么样？（高地址在上，低地址在下）：
	高地址
	┌──────────────────┐
	│ 返回地址 (RIP)    │ ← ret 会跳到这里
	├──────────────────┤
	│ 保存的 RBP        │
	├──────────────────┤
	│ buf[16]          │ ← gets() 往这里写
	└──────────────────┘
	低地址
	
> 	没有 Canary
> 	
> 	buf
> 	↓↓↓↓↓↓↓↓↓↓↓↓↓↓↓
> 	
> 	┌──────────────┐
> 	│ 返回地址      │ ← 可以被覆盖
> 	├──────────────┤
> 	│ buf          │
> 	└──────────────┘
- RBP：RBP（Base Pointer，基址指针）就是"当前函数栈帧的固定参考点"。在函数执行期间通常保持不变，编译器通过 `rbp-偏移量` 来访问局部变量，因此它是**固定参考点**
- RSP：指向当前栈顶（一直在变。）
- 程序在计算一个地址，地址 = ((MRND % 8) + 32) × 4096
```
push rbp
mov rbp,rsp 函数初始化，同时指向栈顶（栈底）
```
- 栈保护如何解决（在buf和返回地址之间放一个随机数）：其实保护的是返回地址
	高地址
	┌──────────────────┐
	│ 返回地址          │
	├──────────────────┤
	│ Canary           │ ← ★ 新增
	├──────────────────┤
	│ buf[16]          │
	└──────────────────┘
	低地址
- 原理：
	在buf和返回地址之间加一个随机数（地址），进入函数的时候先保存canary，如果有人写过头了就是把canary部分也写上了，那么最终程序结束的时候就可以报栈溢出。
- 函数在栈上的数据总体来说是从高地址向低地址增长（压入）的，所以push的时候rsp会减小，pop的时候rsp会增大。
- NX:不可执行保护。能写的内存不能执行，能执行的内存不能写。平时的栈、全局变量区是可写的但是是不可执行的。

### 函数内容补充

- `getenv()` 返回的是字符串，`sscanf()` 负责把字符串变成整数。去掉末尾的/0
- Linux：**一页（Page）就是 4096 Byte（0x1000）** 因为在 Linux 操作系统中，内存管理是以页（Page）为单位的，一页的大小刚好就是 **4096 字节**（也就是十六进制的 `0x1000`）。`mmap` 申请内存时，起始地址必须是 4096 的倍数（也就是**对齐到页边界**）。
- 函数开辟空间是向低地址开辟，**栈向下长**，决定了“后进栈的函数（局部变量）”处于比“先进栈的数据（返回地址）”更低的地址。但是在每一块区域填入数据的时候是向上填入的。
【高地址】 ↑
          │  ...
          ├────────────────────────────┤
          │  返回地址 (main 函数的 ret) │  ← 你的终极目标
          ├────────────────────────────┤
          │  旧的 RBP 值                │
          ├────────────────────────────┤
          │  局部变量 / 其他数据         │
          ├────────────────────────────┤
          │  buf$[63]$                   │  ▲
          │  ...                       │  │  gets() 写入的方向
          │  buf$[1]$                    │  │ (从低地址往高地址填)
          │  buf$[0]$                    │  │
          ├────────────────────────────┤
          │  (栈顶剩余的16字节空闲)       │
【低地址】 └────────────────────────────┘  ← RSP 此时指向这里
- `ret` 指令在硬件层面的本质工作就是：
> “从当前的 **RSP（栈顶）** 弹出 8 个字节，扔进 **RIP（指令寄存器）** 里，然后 CPU 接下来就去执行 RIP 指向的地址。”
- 栈的增长方向是从高地址向低地址增长，但是数据写入方向是从低地址向高地址写入，栈的增长方向是指经历不同函数会依次开辟栈，这样的增长方向是向低地址增长的。

### __libc_start_main
在我们的认知里，`main` 函数是程序的起点。但实际上，在 Linux 系统中，`main` 并不是第一个执行的函数。

当程序启动时，操作系统首先会调用 C 语言运行库（glibc）的初始化函数，即 `__libc_start_main`。这个函数做完准备工作后，再去调用你的 `main` 函数：

$$\text{\_\_libc\_start\_main} \longrightarrow \text{调用} \longrightarrow \text{main()}$$

因此，**`__libc_start_main` 是 `main` 的“爸爸”（调用者）**。

### valgrind
它是一个**用于内存调试、内存泄漏检测以及性能分析的开源工具套件**。
- Valgrind 的核心能力 (Memcheck)
	Valgrind 包含多个工具，其中最常用、也是默认运行的子工具叫 **Memcheck**。它可以精准检测出以下致命的 C/C++ 内存错误：
	1. **内存泄漏 (Memory Leak)**：比如我们刚才代码里 `malloc` 了心跳包但忘记 `free` 的问题。Valgrind 会在程序结束时生成一份详细的“泄漏报告”，告诉你泄漏了多少字节。
	    
	2. **使用未初始化的内存 (Uninitialized Values)**：比如刚才代码里的 `err` 和 `written` 变量。如果程序的分支逻辑基于这些垃圾值进行判断，Valgrind 会立刻报出 `Conditional jump or move depends on uninitialised value(s)` 的警告。
	    
	3. **越界读写 (Out-of-bounds Read/Write)**：比如那个类似“心脏滴血”的漏洞（读取超过实际分配大小的堆内存），或者栈溢出。
	    
	4. **释放后使用 (Use-After-Free, UAF)**：使用了已经被 `free` 掉的指针。
	    
	5. **重复释放 (Double Free)**：对同一个指针 `free` 两次引发的崩溃。
